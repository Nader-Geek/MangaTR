## 1. Architecture overview [read]
- FastAPI sidecar `MB/app.py` (629 lines) with routers in `MB/routers/` (detection, ocr, inpainting, segmentation, splitter, translation, export, pipeline batch, model_install, model_downloads, cache, warmup...).
- Stage order in batch: detect -> ocr -> translate -> segment -> clean(inpaint). Typeset/export: `MB/pipelines/export_pipeline.py` (detect -> OCR -> inpaint -> PSD; stage failures degrade to previous output and are reported in `degraded_stages`), `MB/utils/psd_exporter.py`, `MB/utils/photoshop_text_layers.py`. Typesetting itself (font fitting) happens in the TS frontend [inferred; backend only has `services/typography_shapes.py` contour-based bubble shape/inner-box detection and `models/detection/font*` font classifiers].
- Heavy CPU work is offloaded (`utils/workers.py run_native`) and inference goes through a bounded pool (see section 8).

## 2. Inpainting model contracts
Files: `MB/models/inpainting/{base_inpainter,registry,factory,storage}.py`, `aot/inpainter.py`, `lama/inpainter.py`, `MB/models/onnx_utils.py` [read].
- **Shared contract** (`BaseInpainter`): input RGB uint8 HxWx3, mask (H,W) or (H,W,1) uint8/bool, binarised at >=128; output RGB uint8 same size. Hard cap `_MAX_IMAGE_PIXELS = 32_000_000`. Inputs are borrowed, never mutated; empty mask returns copy. Compositing happens exactly once and never alters pixels outside the binary mask.
- Subclass only implements `forward(padded_image, padded_mask, config)` and must return uint8 of exactly the padded shape (`InpainterOutputError` otherwise). Class vars: `pad_mod` (8), `min_size`, `pad_to_square`. Padding is `np.pad(mode="symmetric")`, then cropped back.
- `InpaintConfig` (frozen pydantic): `hd_strategy` default RESIZE; `hd_strategy_resize_limit=960`; `hd_strategy_crop_trigger_size=512`; `hd_strategy_crop_margin=512`; `mask_feathering=5`.
- HD strategies: ORIGINAL (full image); RESIZE when longest side > limit: downscale image with INTER_AREA, mask with INTER_NEAREST UNION `INTER_AREA coverage>0` (conservative, keeps thin strokes), run, upscale LINEAR; CROP when longest > trigger: per-connected-component box (`boxes_from_mask`, RETR_EXTERNAL), expanded by margin and clamped (`expand_crop_box`), duplicate crops dedup'd, each pixel "owned" by first crop that covers it (`remaining` mask) so overlapping crops don't double-write.
- Final blend (`blend_with_mask`): Gaussian-blurred mask (kernel 2*feather+1) as alpha, but alpha multiplied by the hard mask support so nothing outside the original mask changes; processed in 256-row bands to bound float32 memory.
- **LaMa** (`lama_manga`): image /255 NCHW float32, mask {0,1} NCHW float32; output range ZERO_ONE; if ONNX has fixed HxW it resizes in and out (mask via INTER_AREA >0).
- **AOT**: image to [-1,1] (`/127.5 - 1`) and multiplied by `(1-mask)`; output MINUS_ONE_ONE; `pad_mod=8`, `min_size=128`, `max_size=1024` (downscales longer side first); refuses fixed-shape graphs >1024.
- ONNX wrapper `ImageMaskOnnxModel`: lazy load under lock, resolves image vs mask input by metadata (`resolve_image_and_mask_inputs`), validates float32 NCHW, derives `fixed_hw`, maps ORT OOM at load to `GpuOutOfMemoryError`; `output_to_u8` clips per declared range, rejects NaN/Inf. Normalisation comes from the declared export contract, never guessed from pixel stats (explicit comment).
- Registry (`registry.py`): specs `aot` (ogkalu/aot-inpainting, aot.onnx 23 MB), `lama_manga` (ogkalu/lama-manga-onnx-dynamic), `opencv_lama` (opencv/inpainting_lama, cpu_only), `lama_fp32` (Carve/LaMa-ONNX 512x512, cpu_only); sha256 pinned. `AUTO_PREFERENCE = (lama_manga, lama_fp32, opencv_lama, aot)`. Engines cached in `LruEngineCache(4)` keyed by (model, providers, path, ...).
- **Pre-model heuristics** (`MB/utils/inpaint_heuristics.py`): `apply_need_inpaint_heuristic` per connected component of the mask (area>=9): sample a ring (RING_RADIUS=4, >=24 unmasked pixels); if ring gray std<=8, max-channel std<=9, mean HSV saturation<=18, fill component with ring median colour and drop it from the model mask (flat bubbles never hit the network). Budget guards: <=10,000 components, ROI work <= 4x image area. `detect_background_complexity` (Sobel gradient >12 on >15% of context ring pixels => "complex") picks CROP vs RESIZE when strategy unspecified (`batch/stages.py _resolve_hd_strategy`). Result label `hybrid:<model>` when some components were solid-filled.
- **Mask build** (`MB/utils/mask.py generate_baka_style_mask`): per region uses an optional segmentation PNG mask, else merged_boxes / segment_boxes / bbox; morphological close at downscaled long edge 2048; then elliptical dilate (`mask_dilation` default 5) [read].
- Cache: clean stage key = image hash + mask fingerprint + settings fingerprint (`pipelines/stage_store.py`, `build_clean_cache_key`) [read].
- Weaknesses: ORT-only, no torch inpainter path; no mask-aware context for very large crops; fixed 8-pad modulo and symmetrical pad can leak texture into edge text; AOT/LaMa weights have unclear licences; `mask_feathering` default of 5 may halo on screentoned bg [inferred].

## 3. Comic Text Detector usage (text mask)
File: `MB/models/detection/comic_text_detector/detector.py` (236 lines) [read].
- **Only the block/box head is used. The text-segmentation mask output is NOT consumed** (`self.session.run(None, ...)[0]` -> `blk`; no mask/line outputs read). So "text mask" in koma comes from elsewhere: the separate segmenter (section 4) or box rasterisation (`utils/mask.py`). [read]
- Preprocess: resize whole slice to 1024x1024 (no letterbox, aspect distorted), RGB/255, NCHW. Output rows `[cx, cy, w, h, obj, cls0, cls1, ...]`; score = `obj * max(cls0, cls1)`.
- Constants: default conf 0.15; min box 6 px; aspect filter reject >30 or <0.03; NMS threshold from config (`detection_nms_threshold`) via `cv2.dnn.NMSBoxes`; recall pass: if <2 merged boxes found, retry at threshold `max(0.05, min(conf*0.5, 0.10))` and re-merge.
- Tall-strip slicing (`models/detection/slicing.py`): if H/W > 3.5, slices of height `W*3.0`, overlap 20%, last-slice min height ratio 0.7; detections offset back to page coordinates.
- Line merge (`_merge_text_lines`): paint boxes into mask, dilate with rect `(max(9,kx//2), ky)` where kx=clamp(0.035*W,14..64), ky=clamp(0.02*H,12..56) (odd-forced), then close with `(max(11,kx), max(11,2*ky))`, findContours -> boxes; drop components < `max(200, 0.00002*W*H)` px; score = max overlapping det score else 0.2.
- Reading order: `models/detection/reading_order.py` (line-band ratio 0.5, flow votes in 256 blocks, orientation inference).
- Other detectors present: `pp_doclayout_v3`, font detectors; factory `detection/factory.py` [read heads only]. Fallback logic in `utils/detection_fallback.py` [not read].
- Weaknesses: aspect-distorting resize hurts small text on non-square pages; merge dilation is page-size heuristic (merges adjacent bubbles on dense pages); score synthetic 0.2 fallback; slice NMS not done across slice seams until final NMS [inferred]. GPL: see section 0.

## 4. Splitter / segmentation
- **Content segmenter** `MB/models/segmentation/baka_segmenter.py` (`BakaContentSegmenter`, key `baka_content_cc`) [read]: per OCR region crop, Otsu threshold; both polarities (dark<=t and light>t) -> `connectedComponentsWithStats` (8-conn, min area 10 px, border margin 1); boxes expanded vertically 10%; drop sides <5 px; merged via closing a (possibly downscaled to long edge 2048) canvas with 15x15 kernel, padding 8, side >=2. Returns page-sized PNG mask (base64) per region; output budget 64 MB, pixel budget 32 M. This is a classic CV text-pixel segmentation, not a neural one. Weakness: Otsu fails on gradient/textured bubbles; per-region full-page masks are memory heavy (acknowledged in module doc).
- **Long-strip splitter** `MB/services/splitter_analysis.py` (`analyze_strip`) [read]: gray, Gaussian blur (1x9) of the row-mean projection; whitespace threshold `170 + round(sensitivity/100*70)`; scan from `min_size` (floor 80); cut when brightness>=threshold, min segment spacing, trailing remainder >= min/2, edge guard >=8; `protectTallBlocks`: if run since last cut > 1.2*max_size require brightness >= threshold+16; segments get overlap; tiny <400 px warning. Also fixed-height (min step 100) and count strategies. Axis-agnostic via transpose. Weakness: row-mean brightness only (no dark-gutter/screentone detection; black-gutter pages unsupported) [inferred].

## 5. Glossary and never-translate
- Parsing/limits `MB/core/config.py` [read]: max 200 terms, source <=120 chars, target <=240 chars; `GlossaryTerm(source, target, never_translate)`.
- **Prompt path (cloud/LLM)**: `models/translation/prompts.py format_glossary_block` -> "Glossary - when a source term below appears, translate it exactly as given:\n- src => tgt" appended to extra context (`compose_translation_extra_context`). System prompt also forbids translating proper names, currency, etc.
- **Masking path (local engines only)**: `MB/pipelines/translation_masking.py` [read]. `build_term_pattern`: case-insensitive, `(?<!\w)(...)(?!\w)`, longest term first. `plan_masked_segment` splits text into steps `term | literal | run` (runs keep original pre/post whitespace; no-alnum chunks are literals). Only runs go to the model (deduped, ONE batched call via `translation_stage._translate_masked`); `reassemble_masked` restores terms verbatim. If all alnum content is protected, no engine call. Blank run output raises `BlankRunTranslationError` (retryable in fallback chain) rather than splicing a hole.
- Post-check `glossary_missing` (`translation_qa.py`): for local engines in non-SFX mode, note if a term's source is in the source but expected target absent. Notes only, never rewrites.
- Parity guard: cache/TM hits from local engines are discarded if they lack protected terms verbatim (`_contains_protected_terms`).
- Weaknesses: regex word-boundary `\w` fails for CJK (no boundaries, but lookarounds still allow matches); no inflection handling; glossary post-check is substring-exact; cloud engines get no enforcement, only a prompt hint [inferred].

## 6. Translation quality checks
`MB/pipelines/translation_qa.py` (368 lines) [read]. Notes (prefix `NT: `, Portuguese strings) not failures; only rewrite is echo collapse.
- Detectors: `empty`; `identical` (same text under NFKC+casefold but different script, e.g. fullwidth) ; `foreign_residue` (CJK/Hangul run >=2 chars in non-ja/zh/ko target; regex ranges ぀-ヿ, 㐀-䶿, 一-鿿, 豈-﫿, 가-힯); `repeated_word` (content word >=3 letters repeated >=2x in target while source repeats nothing; source contractions expanded first so "I'm ... I'm" is not blamed; EN+PT function-word stoplist exempt); `length_ratio` (source len >=8; CJK->Latin bounds 0.25-5.0, Latin->Latin 0.58-3.2; script derived via `unicodedata.name`, so `auto` source works).
- `repair_echo`: only if a word repeats >=3x; candidates R1 (X+X half split) then R2 (collapse adjacent equal tokens); adopted only if non-empty, != source, and re-passes echo/residue detectors. Echo-repaired results never enter TM.
- SFX mode skips heuristic detectors. Weakness: PT-BR-specific notes/stoplist; script detection by first word of Unicode name is coarse; no semantic/back-translation check [inferred].
- JSON response parsing tolerant: `models/translation/parsing.py` (code fences, id-map, key aliases `text|translated_text|translation`, notes aliases, single-region fallbacks).

## 7. Translation memory / cache (3 tiers)
`MB/pipelines/translation_store.py` + `translation_stage.py run_cached_translation` [read].
1. In-memory pipeline cache (`pipeline_cache.cache_translation_results`, per cache_key) - first.
2. Persistent sqlite (WAL, one connection + lock, schema v1, `_DEFAULT_MAX_ROWS=200_000`, `_QUERY_CHUNK=500`) in `KOMA_APP_DATA_DIR`: table `translation_cache(key sha256, translated_text, notes, engine_key, created_at)`. Key = sha256 of JSON `[1, model_key, src, tgt, mode, normalize_source_text(text), glossary_sha1]`; **page context deliberately excluded** so restarts/pages reuse. `normalize_source_text` = NFC + strip + collapse whitespace. `glossary_hash` = sha1 over ordered (source,target,never_translate).
3. Translation memory table `tm(nfkc_key, src_lang, tgt_lang, translation, model_key, hits, updated_at)`: exact NFKC key only, **no fuzzy matching**; reads are opt-in (toggle), writes always on except SFX; written only when output non-empty, not echo-repaired, and normalised text != normalised source; hits bump counters in one batch; batched IN reads (no N+1).
- Also: identical texts in a request are deduped to one representative (`dedup_reps/dedup_members`) and QA verdict replicated to members; store failures degrade gracefully (`_warn_store_degraded`).
- Weaknesses: no fuzzy/TM-edit workflow, no per-project scoping, cache ignores context by design (same line translated differently by scene is lost); `prune` is row-count based [inferred].

## 8. GPU/OOM fallback and execution
- OOM detection `MB/core/runtime_errors.py is_insufficient_memory_error` [read]: MemoryError or flattened exception chain (`__cause__/__context__`) containing patterns: "bfc_arena::allocaterawinternal failed to allocate memory", "failed to allocate memory for requested buffer", "cuda out of memory", "cudnn_status_alloc_failed", "cublas_status_alloc_failed", "not enough memory", "insufficient memory", "unable to allocate".
- `MB/services/device_fallback.py run_with_cpu_fallback` [read]: run once; on any Exception: run OOM-transition releasers + `release_gpu_memory(force=True)`; if `use_gpu` and OOM -> retry exactly once with `build_cpu_device_info(..., fallback_reason="gpu_runtime_out_of_memory")`; else `ExecutionFailedError`; CPU failure -> `CpuFallbackFailedError`. `FileNotFoundError` (model absent) and `InferenceBusyError` pass through. Reports via headers `X-Koma-Execution-Fallback: gpu_oom_to_cpu` (HTTP) or `fell_back_stages` (batch).
- `release_gpu_memory`: gc.collect + `torch.cuda.empty_cache()` + `ipc_collect()`, skipped while GPU "leases" are active unless forced (`MB/core/device.py` ~L930-989). `release_onnx_gpu_memory` calls registered cache releasers (engine LRUs) so ORT arenas drop. Per-stage release after detect/ocr/clean (opt-out env `KOMA_SKIP_GPU_RELEASE`).
- Pre-load VRAM probe for torch VLM OCR (`models/ocr/transformers_vlm/engine.py` ~L197): `torch.cuda.mem_get_info()`; if free < declared min -> load on CPU with reason `vram_to_cpu` (best-effort; probe failure keeps GPU).
- ORT sessions: `create_session_with_trt_fallback` retries once without TensorRT; provider selection/profile detection (cuda/rocm/dml/openvino/cpu, CUDA legacy options, DLL repair) in `core/device.py` (989 lines).
- Inference admission `MB/models/execution.py` [read]: `ThreadPoolExecutor(min(4, cpu_count))`, outstanding limit = 2x workers via non-blocking `BoundedSemaphore` -> `InferenceBusyError` (HTTP 503 INFERENCE_BUSY); cancellation of an awaiter still waits for the running native call (inputs stay borrowed).
- Weaknesses: a single retry on CPU only (no tile-size reduction / smaller-resolution retry on GPU); OOM matching is string-based [inferred]; large VLMs can be unusably slow on CPU.

## 9. Job queue / batch orchestration
- `MB/pipelines/queue_processor.py QueueProcessor` [read]: generic bounded-concurrency pool of N worker coroutines pulling from a shared iterator (TaskGroup), per-task `asyncio.timeout`, fault isolation (exceptions -> item error), `continue_on_error`, external `asyncio.Event` cancellation, results kept in input order; unprocessed items marked "batch aborted".
- `MB/pipelines/batch/orchestrator.py BatchOrchestrator` [read]: `PER_IMAGE_TIMEOUT_SECONDS = 1200` (extrapolated, not measured per comment); two-phase mode when neighbour-image context is on (phase 1 detect/OCR for all pages, then phase 2 translate with neighbour OCR context, `_NEIGHBOR_MAX_ITEMS=8`, `_NEIGHBOR_MAX_CHARS=800`); spooled uploads are read only once a concurrency slot is held; item status success/partial/failed via `resolve_item_status`; effective vs requested concurrency reported with a note; progress sink (`batch/progress.py`); cleaned pages zipped (`batch/archive.py`).
- Download jobs `MB/core/download_jobs.py` [read]: single worker thread, FIFO (avoids HF 429s), states queued/downloading/verifying/ready/error/cancelled, error codes network/disk_full/checksum_mismatch/rate_limited/cancelled, speed window 5 s, disk precheck slack 10% (floor 64 MB), keeps 20 finished jobs; HF downloader `core/hf_download.py` with sha256 verification.
- Weakness: batch state is in-process (no durable job queue/resume) [inferred]; one global GPU pool shared by stages.

## 11. Provider routing
- **Translation fallback** `MB/models/translation/fallback.py` [read]: `validate_translation_chain_keys` (fail fast: unknown / not implemented / not available); `translate_with_fallback` iterates chain; retryable errors = `TranslatorUnavailableError, TranslatorResponseError, LocalModelError, EmptyTranslationError, BlankRunTranslationError`; config/language errors re-raised; `QuotaBlocklist` blocks a key for the rest of the local calendar day after `TranslatorUnavailableError` (in-memory, per process); `FallbackResult` carries per-attempt records. Whole-attempt empty output raises `EmptyTranslationError` so the chain advances.
- Providers (`models/translation/providers/`): OpenAI-compatible, Gemini, Claude, DeepL, Google, MS, Yandex, LibreTranslate, request-scoped custom (`request_scoped.py`; min timeout 5 s); LLM max output 4096 tokens (`_llm_base.py`); `core/http_retry.py` retries 429/502/503/504 honouring Retry-After clamped 1-10 s, fallback delay attempt+1 s.
- **Discord bot router** `apps/discord-support-bot/provider_router.py` [read]: priority list from `LLM_PROVIDER_PRIORITY` env or a 31-provider free-tier fallback tuple (openrouter, groq, cerebras, google_ai_studio, ...); catalog scraped by regex from the frontend TS provider file (`TOP_LEVEL_PROVIDER_PATTERN`) - brittle; providers enabled by `<PREFIX>_ENABLED` or API key; transports openai-compatible, `gemini_native`, `nlp_cloud_chatbot`, `ollama_native`. Failover: rate-limit/quota error -> per-provider cooldown (`LLM_RATE_LIMIT_COOLDOWN_SECONDS`, default 300 s) + next; temporary/other errors -> next without cooldown; heuristic text classifier for non-429 quota messages ("rate limit", "quota", "resource_exhausted", "tpm", "rpm", "requests per day", ...); raises after exhausting with first 5 error details. Bot also has RAG (`rag_engine.py`, LlamaIndex + lexical fallback), not relevant to translation.
- Weaknesses: translation chain blocklist is whole-day and in-memory; discord router is sync httpx and sequential; the regex catalog parse breaks if TS formatting changes [inferred].
